## 4. 必须披露的判据设计缺陷（我的）

v2 判据 3 写的是"两臂在最后 20% 的 eval return **均单调不减**"。
实测 **6 条曲线无一满足**——包括表现最好的 `iface s1`（632→597 就已下降）。

在有噪声的 RL 训练曲线上，**严格单调不减几乎恒假**，于是判据 4 变成
"1、2 不满足时的必然结果"。这正是 CLAUDE.md §8.4 警告的形态：
前置条件的写法蕴含了结论，使某个分支逻辑上不可达。

**因此必须区分两个结论的强度：**

- **"不能进入 Phase 1"是稳固的**——它只依赖主判据（1/3 正），
  与曲线检查无关，不受本缺陷影响。
- **"永久关闭整条路线"的辨别力是打折的**——判据 3 与 4 的区分
  （"接口无效" vs "预算不足"）因判据 3 恒假而失效。

按 §8.7，**我不在同一批数据上修改判据**。若未来要重启这条路线，
须新写预注册，把"单调不减"改为可操作的形式（例如尾段线性拟合斜率 > 0，
或末点显著高于尾段起点），并用**新 seeds** 独立执行。

## 5. 描述性观察（不进裁决）

| seed | flat `hand_dist` | iface `hand_dist` | flat `target_dist` | iface `target_dist` |
|---|---|---|---|---|
| 1 | 1.0615 | **0.5776** | 0.5376 | **0.3081** |
| 2 | 0.5322 | 0.8472 | 0.2737 | 0.3437 |
| 3 | 1.1616 | **0.4228** | 0.2920 | 0.3670 |

**seed 3 最具信息量**：iface 的 `hand_dist` 好得多（0.4228 vs 1.1616，
手离 box 近得多），但 `target_dist` 更差（0.367 vs 0.292，box 没被推到位），
return 反而是负的（−171.58），成功率仅 0.031。

这与官方结论和 capability-coverage 论点一致：**低层 reaching controller 只会
"把手移到目标位姿"，不会"推动物体"**；而且它只输出 19 维 body action、
**不控制手**（`wrappers.py:105`，`TorchModel(55, 19)`）。
于是接口让机器人更会**接近** box，却没有把 box 推向目标的能力。

方差同样值得记录：`iface s1` 末点 712.20 是全场最高，`iface s3` 全程为负。
`n=3` 无法分辨"接口有时极有效"与"随机波动"。

## 6. 这个结果不能说明什么

1. **不是迁移结论**——两臂差异是控制接口，不涉及 source→target 知识迁移。
2. **不否定官方 HumanoidBench 的 Push 结论**——官方用的训练预算、算法与
   评估口径都与本轮不同；本轮只说明"在我们的 FastTD3 栈 + 100k 预算下不成立"。
3. **不推翻主线任何 verdict**；truck 的 20k 负 / 95k 正（+229.9, t=3.47）
   仍然成立，"固定 policy 载体不行"依旧未被证实。
4. 100k 只有官方 push 默认 1M 的 1/10，**预算不足这一可能性没有被排除**
   （正是判据 3 本该分辨、却因措辞失效的那一点）。
