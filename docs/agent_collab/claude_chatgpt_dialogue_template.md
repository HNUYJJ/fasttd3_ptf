# Claude–ChatGPT 共享对话文档模板

> 本文档是 Claude 与 ChatGPT 跨会话协作时的共享事实源和交接日志。
> 使用前填写“会话信息”；开始协作后，双方只在文末追加自己的轮次，
> 不删除、不改写已经完成的历史轮次。

## 一、用途

本模板用于让 Claude 与 ChatGPT 在彼此不能直接共享聊天上下文时，通过同一个
Markdown 文档交换完整回复、证据、问题和下一步行动。它适合研究审查、方案讨论、
代码协作、故障诊断和文档撰写等需要多轮交接的工作。

本文档只负责传递可见上下文，不代表两个模型建立了实时连接，也不会自动授予任何
终端、文件、网络、账户或外部服务权限。

## 二、会话信息（首次使用时填写）

- 会话 ID：`<YYYYMMDD-topic-slug>`
- 主题：`<本次协作主题>`
- 总目标：`<最终希望得到的结果>`
- 当前范围：`<允许分析或修改的文件、模块、系统>`
- 明确排除：`<本轮不处理的内容>`
- 关键约束：`<语言、格式、时间、成本、安全或实验约束>`
- 人类负责人：`<姓名或“用户”>`
- 默认首位回复者：`<Claude | ChatGPT>`
- 创建时间：`<ISO 8601 时间，注明时区>`

## 三、参与者与权限

- `Human`：提出目标、补充信息、解决分歧，并批准高成本、破坏性或对外产生影响的操作。
- `Claude`：只记录 Claude 自己实际生成的内容，不得代写 ChatGPT 的回复。
- `ChatGPT`：只记录 ChatGPT 自己实际生成的内容；若通过 Codex 工作界面参与，仍使用
  `ChatGPT` 作为本文档中的角色名，并可在“执行环境”字段注明 `Codex`。

任何一方都不得仅凭本文档推断自己拥有额外权限。删除数据、覆盖重要文件、启动昂贵
训练、提交或推送代码、发布内容、发送消息以及修改外部系统前，仍须获得用户明确授权。

## 四、强制对话规则

1. **回复前先读文档。** 每轮开始时，当前回复者必须先读取本文件的会话信息、规则、
   最后一条完整轮次，以及最后一条轮次引用的必要上下文；之后才能形成回复。
2. **写入前再次刷新。** 准备追加回复前必须重新读取文末，确认没有另一方刚写入的新
   轮次，并据此选择下一个未使用的轮次编号。
3. **默认轮流回复。** 默认按 `Claude → ChatGPT → Claude` 或用户指定的相反顺序交替。
   同一角色连续回复时，必须在“轮次类型”中标为 `follow-up` 并说明原因。
4. **一轮一个写者。** 同一时刻只允许一方编辑本文档。每一轮只追加一个完整区块，
   直至写入对应的 `END TURN` 标记后才算完成。
5. **只写自己的真实回复。** 不得伪造、补写、改写或替对方概括成一条“对方回复”。
   如需概括对方观点，必须注明这是自己的转述，并引用对方轮次编号。
6. **完整记录，避免失真。** “回复正文”应保存本轮希望对方和用户看到的完整实质内容，
   不能只留下“已完成”“同意”等无法恢复上下文的短句。
7. **区分事实、推断与建议。** 重要结论应给出文件、代码行、日志、命令输出、链接或
   对话轮次等证据；未核实内容必须明确标为推断或待验证。
8. **保留分歧。** 双方意见冲突时不得覆盖旧结论，应在新轮次中写明分歧、依据和建议的
   判定方法。用户最新指令优先于双方旧提议，可验证证据优先于无证据断言。
9. **不得泄露秘密。** 不在本文档中记录密码、令牌、API key、私钥、个人敏感信息或
   未经许可的机密内容。必要时只记录安全的变量名或脱敏占位符。
10. **失败也要记录。** 命令失败、权限不足、文件缺失或结论不确定时，如实记录现象和
    阻塞原因，不得把计划执行描述成已经成功。
11. **控制重复。** 已存在的长背景优先用轮次编号或文件路径引用；只有为避免误解所必需
    时才重复粘贴。
12. **明确交接。** 每轮结尾必须指定下一位回复者、需要其回答的问题，以及是否需要用户
    批准。没有实际问题时写 `无`，不得省略字段。

## 五、每轮开始前检查清单

当前回复者必须在内部完成以下检查；若无法读取文件或发现上一轮没有完整的
`END TURN` 标记，应暂停追加并向用户说明问题。

- [ ] 已确认文件路径和会话 ID 正确。
- [ ] 已读取会话目标、范围和约束。
- [ ] 已找到编号最大的完整轮次。
- [ ] 已读取对方上一轮的“回复正文”“问题”和“交接要求”。
- [ ] 已核实本轮编号、回复对象和当前写者。
- [ ] 写入前已再次刷新文末，排除并发更新。

## 六、统一轮次格式

每次回复必须复制下面的完整区块并追加到“对话记录”末尾。轮次编号采用四位递增数字，
例如 `T0001`、`T0002`。时间使用 ISO 8601 格式并注明时区。

```markdown
## T0001 | Claude | <YYYY-MM-DDTHH:MM:SS+00:00>

- 轮次类型：`response`  <!-- response | follow-up | correction | final -->
- 回复对象：`Human 初始任务`  <!-- 或 T0000、T0001 等 -->
- 执行环境：`Claude Code`  <!-- ChatGPT、Codex、Web 等 -->
- 当前任务焦点：`<一句话说明本轮处理的问题>`
- 状态：`completed`  <!-- completed | partial | blocked -->

### 回复正文

<写入本轮完整、可独立理解的实质回复。>

### 证据与产物

- `<文件路径、代码行、日志、命令结果、链接或“无”>`

### 对上一轮的判断

- 同意：`<同意的结论或“无”>`
- 修正：`<需要修正的内容、依据，或“无”>`
- 待验证：`<仍需验证的内容或“无”>`

### 建议的下一步

1. `<按优先级列出下一步；没有则写“无”>`

### 给下一位回复者的问题

1. `<明确问题；没有则写“无”>`

### 用户批准需求

- `<需要用户批准的动作及原因；不需要则写“无”>`

### 交接

- 下一位回复者：`ChatGPT`  <!-- Claude | ChatGPT | Human -->
- 下一轮应先读取：`T0001` 及 `<必要文件或“无”>`

<!-- END TURN T0001 -->
```

## 七、首次启动方式

1. 将本模板复制为一个新的会话文件，推荐命名：
   `claude_chatgpt_<YYYYMMDD>_<topic>.md`。
2. 填写“会话信息”，但保留规则和格式定义。
3. 把文件路径和任务告诉首位回复者，并使用以下启动提示：

```text
请先完整读取 <共享对话文档路径>，严格遵守其中的角色、轮次格式和追加规则。
读取最后一条完整轮次及其交接要求后再开始工作。你只能追加自己的回复，不得改写
已有轮次，也不得代写另一位代理的回复。完成后请把本轮完整内容追加到文档末尾。
```

4. 切换到另一位回复者时，提供同一文件路径并重复上述提示。后续双方均以文档中最后
   一条完整轮次为交接起点。

## 八、中断、恢复与结束规则

- **中断恢复：** 新会话接手时先读取全文规则、会话信息和最近两条完整轮次；如任务较长，
  再按最新轮次引用回溯必要证据。
- **损坏恢复：** 若文末存在没有 `END TURN` 的半成品轮次，不得自行猜测其内容；由原写者
  补全，或由用户明确决定删除/封存该半成品。
- **更正历史：** 不修改旧轮次。使用新的 `correction` 轮次指明被更正的轮次、错误和新证据。
- **结束会话：** 最后一位回复者使用 `final` 轮次，总结已达成结论、未解决事项、产物路径和
  后续恢复方式，并把下一位回复者设为 `Human`。
