## 5. 三个可核对的结论

**(1) "实现冻结后零代码改动"这次是自证的。** `evaluation_semantics_digest`
覆盖 `schema_version` + `source_free_mode` + 三个语义文件的内容摘要。
`smoke.json` 记录 `80619b7e…`，结果提交时重算一致，且
`git diff 0bd8640 -- <三文件>` 为空。上一轮只能口头声明。

**(2) 检测器先被证明会响，"没响"才成为证据。** inventory sentinel 报告
"0 个文件名↔内部身份冲突"——这本身无信息量。故注入两个人为冲突
（改错 seed / 改错 step，写临时目录跑完即删），2/2 均被识别。

**(3) `first_hit_step` 在真实数据上与 `first_step` 分离。** basketball 实测
`first_step=0` 而 `first_hit_step=9`。若把前者实现成后者的别名（很容易犯的错），
这里会露馅。

## 6. Known limitations

### 6.1 evaluator

1. **`max > final` 的回落在 runtime 一次都没出现**（truck 0/0、bookshelf 0/0、
   basketball 1/1）。D3 所修的具体故障仍只有单元测试 `T11/T11b/T11c` 覆盖。
   不得把 S6/S10 的 PASS 读成"已证明能抓住回落"。
2. **S3/S4 的终止语义未验证**（0/8 终止），已被 `scientific_use_blocked` 拦截；
   bookshelf 在真实 termination path 验证前不得进 P3 裁决。
3. **bookshelf 的 milestone 只验证了低值区间**——其成功事件与终止 reason 1
   是同一事件，终止既未发生，高值区间必然也未被观察到。
4. **formal 模式从未在真实 checkpoint 上端到端跑过。** smoke 全走 debug，
   formal 强制性由 `T16` 系列在构造的 checkpoint 上验证。
   **第一次真实 formal 评估将发生在 P3 之前，届时须单独确认一次。**
5. **identity manifest 没有生成器**，须手工写或由 P2 inventory 产出。
   否则 formal 在实践中会因"太麻烦"被绕开。
6. **claim linter 是行级正则**，能挡原措辞回流，挡不住语义等价的改写
   （如把 impossibility 写成 "cannot in principle"）。它是护栏不是判官。
7. `schema_version` 升到 2.2 是破坏性变更，旧扁平 milestone 格式已移除。

### 6.2 inventory

8. **本轮结论只覆盖 20 个文件**，不得外推到全部 1661 个。
9. **FINAL 去重路径未被真实触发**（VACUOUS），只有单元测试覆盖。
10. **racing 臂未被覆盖**（`SENTINEL_UNAVAILABLE` 0/2），如实记录未换文件凑数。
11. **`experiment_role` 100% UNKNOWN**——正确的 fail-closed，但意味着 inventory
    目前**不能**回答"哪些是 hard-exit 臂"。
12. **`hard_exit_step` = `UNKNOWN_NO_DEDICATED_KEY`**。已 grep 全仓库确认
    `ptf_cfg` 内无该专用键；它在语义上等于 `mcg_warmup_steps`，但那是设计层解释。
13. **预注册 §4 的 completion 判据有缺陷**：用 `total_timesteps` 而 `ptf_cfg`
    另有 `run_stop_step`（实测 20000 vs 100000），会把"按配置正常结束"的 run
    误判 `TRUNCATED_RUN`。判据已冻结故本轮如实实现未改，仅输出诊断量。

### 6.3 流程

14. **v21b / v21c 两份 protocol 都不是 blind prereg**——写于看过前轮结果之后。
    它们能保证"实现不回头迁就结果"，不能保证"判据独立于已见结果"。
    P2 的预注册（`bf14f20`）对 v2 主终点是盲的，但对 v1 已披露的聚合量不盲。
